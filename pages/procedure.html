ARGON2 (ARGON2ID)

Procedure to be followed

Perform the steps in order. Each step uses the Simulation page (tabs: Hasher, Verify, Memory Grid, Benchmark) or a Demonstration.

Step 1 — Hash a password with recommended parameters

  1. Open the Simulation page, Hasher tab.
  2. Enter a password such as hunter2. Keep Salt on random, m = 19456 KiB, t = 2, p = 1, variant Argon2id, tag length 32 bytes.
  3. Click Compute Hash. Record the PHC string, elapsed time, and memory used (m KiB ≈ m/1024 MiB of RAM).
  4. Click Compute Hash again for the same password. The hash is different — the salt is regenerated each run. This is expected; verification uses the salt stored in the PHC string.

Step 2 — Verify a hash (login flow)

  1. Switch to the Verify tab and paste the PHC string from Step 1.
  2. Enter the correct password → status MATCH. Enter a wrong password → NO MATCH.
  3. Observe that both attempts take approximately the same time — the work factor is fixed by the stored parameters, so there is no timing oracle on the password.

Step 3 — Salt & rainbow tables (Demo 1)

  1. Open Demo 1 — Salt & Rainbow tables.
  2. Hash one password for 3 users, unsalted: the digests are identical, so one precomputed rainbow-table row "cracks" all three accounts at once.
  3. Now enable unique per-user salts: the digests differ, precomputed tables become useless, and the attacker must re-hash guesses separately for every user.

Step 4 — Tune the cost parameters (Demo 2)

  1. Open Demo 2 — Cost-parameter trade-offs.
  2. Measure with (a) m = 8 KiB, t = 1, p = 1; (b) m = 262144 KiB (256 MiB), t = 1, p = 1; (c) m = 19456, t = 2, p = 1 (OWASP interactive minimum); (d) 19456, t = 2, p = 4.
  3. Note how wall-time and memory scale with m and t, and how p spreads work over lanes (threads).
  4. 1 GiB settings are not practical in-browser; servers typically use 19–64 MiB for interactive login — the big-memory figures describe the attacker's hardware cost, not the defender's.

Step 5 — Benchmark Argon2 vs PBKDF2 (Demo 3)

  1. Open Demo 3 — Benchmark.
  2. Run the three profiles: weak (8 MiB, t=1), interactive (19 MiB, t=2), sensitive (64 MiB, t=3), plus PBKDF2-SHA-256 at 600 000 iterations.
  3. Record hashes/second for each. Argon2id burns memory per guess; PBKDF2 burns only throughput. Use this data in Assignment Q7–Q8.

Step 6 — Assignment

  1. Attempt Assignment Q1–Q8.
  2. Support every claim with the demo/simulation step that showed it, e.g.: "Demo 2(b): 256 MiB took X ms → attacker RAM cost scales linearly with m".
