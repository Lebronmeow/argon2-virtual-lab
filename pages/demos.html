Demonstrations

Three guided demonstrations, each running real Argon2id hashing in your browser. Read the story for each demo, click Run, and record the numbers — you will cite them in the Assignment.

Demo 1 — Salt & rainbow tables

Three users — alice, bob, carol — all chose the same password. Run the demo twice: first with a fixed "salt" (emulating an unsalted database — Argon2 itself always salts; this shows what would happen if it did not), then with a unique random salt per user.

Demo 2 — Cost-parameter trade-offs

The same password hashed with four parameter presets. Watch both columns: time (what the user feels at login) and memory (what the attacker's hardware must buy).

Presetm (KiB)tpMemoryTime
Expected pattern: (a) weak — sub-millisecond, 8 KiB; (b) 256 MiB — memory dominates; (c) OWASP interactive minimum — a few tens of ms; (d) p=4 spreads work over 4 lanes (threads) but needs a bigger m to keep the same security.

Demo 3 — Benchmark: Argon2id vs PBKDF2

One guess per configuration, timed. Throughput ≈ 1000 / milliseconds. Multiply by a botnet or a rack of GPUs to see why the absolute number matters less than the hardware cost per guess: PBKDF2 needs only arithmetic, Argon2id needs arithmetic + 19–64 MiB of fast RAM per concurrent guess.
